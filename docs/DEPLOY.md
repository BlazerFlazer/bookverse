# Запуск в интернете

Сайт живёт на Vercel, а сервер и бот на Railway. Сервер нельзя разместить на Vercel: ему нужны постоянно работающий процесс и диск для базы SQLite, а там их нет.

```
Браузер ──► blazverse.vercel.app ──/api──► Railway: сервер + бот + база на диске
   └────────── сокет Demo Day ─────────────►┘
```

Обычные запросы идут через Vercel, поэтому cookie остаются своими для сайта. Сокет Demo Day подключается к серверу напрямую, так как его данные публичны.

## 1. Создать сервис на Railway

1. Зарегистрируйтесь на [railway.com](https://railway.com) через GitHub.
2. New Project → Deploy from GitHub repo → выберите `BlazerFlazer/bookverse`.
3. В настройках сервиса (Settings) укажите рабочую ветку, если правки ещё не влиты в `main`. Railway сам найдёт `Dockerfile` в корне репозитория.
4. Добавьте диск: правый клик по сервису → Attach Volume, путь монтирования `/data`. Без диска база стирается при каждом обновлении.
5. Settings → Networking → Generate Domain. Получится адрес вида `https://bookverse-production.up.railway.app`.

## 2. Задать переменные

Вкладка Variables. Секреты вводятся только здесь и никогда не попадают в репозиторий.

| Переменная | Значение |
|---|---|
| `PUBLIC_WEB_URL` | `https://blazverse.vercel.app`, без `/` в конце |
| `TRUST_PROXY_HOPS` | `2` |
| `TELEGRAM_BOT_TOKEN` | токен от @BotFather |
| `TELEGRAM_BOT_USERNAME` | имя бота без `@` |
| `BOT_INTERNAL_SECRET` | длинная случайная строка, не короче 16 символов |
| `DEMO_PRESENTER_KEY` | ключ ведущего Demo Day |

`PORT`, `NODE_ENV`, `DATABASE_URL` и `BOOKVERSE_API_URL` задавать не нужно. При каждом старте сервер сам применяет миграции и загружает книги, поэтому первый запуск занимает около 30 секунд.

Перед запуском бота на Railway остановите его на своём компьютере. Telegram не разрешает двум процессам получать сообщения одного бота, и второй будет падать с ошибкой 409.

## 3. Проверить сервер

Откройте адрес с Railway и добавьте `/api/health`. Должно появиться `{"ok":true}`.

## 4. Подключить сайт

В `apps/web/vercel.json` добавьте перед имеющимся правилом два правила, подставив свой адрес:

```json
{ "source": "/api/:path*", "destination": "https://АДРЕС-RAILWAY/api/:path*" },
{ "source": "/socket.io/:path*", "destination": "https://АДРЕС-RAILWAY/socket.io/:path*" },
```

Создайте файл `apps/web/.env.production`:

```
VITE_REALTIME_URL=https://АДРЕС-RAILWAY
```

После этого задеплойте проект `web` на Vercel.

## 5. Проверить всё вместе

- Откройте сайт, зарегистрируйтесь, откройте книгу, сохраните слово.
- Обновите страницу на `/library`: она не должна отдавать 404.
- Напишите боту и привяжите аккаунт из профиля на сайте.
- Запустите показ на `/demo` и проголосуйте с телефона по QR-коду.

## Стоимость

Условия Railway на 31 октября 2026 года:

- **Пробный период:** разовые $5 на 30 дней, карта не нужна, до 1 ГБ памяти и 0,5 ГБ диска.
- **Расход:** память стоит $10 за ГБ в месяц. Сервер с ботом занимает около 250 МБ, то есть примерно $2,5 в месяц, плюс процессор и диск.
- **Потом:** тариф Hobby от $5 в месяц, нужна карта. Бесплатный тариф даёт лишь $1 в месяц, этого не хватит для круглосуточной работы.

Запланируйте Demo Day в пределах пробного периода или заранее перейдите на Hobby. Данные на диске пробного тарифа удаляются через 30 дней после его окончания.

## Ограничения

- Счётчик запросов считается по адресу посетителя, но телефоны в одной школьной сети выглядят для сервера как один адрес. Голосование рассчитано на это: у него свой лимит в 1000 запросов в минуту. На обычные запросы действует общий лимит в 600 запросов в минуту, а на вход и регистрацию 20.
- `TRUST_PROXY_HOPS=2` верит заголовку `X-Forwarded-For`. Обратившись к адресу Railway напрямую, можно подделать свой адрес и обойти лимиты запросов.
- Сервер работает в одном экземпляре. Не увеличивайте число реплик: база лежит на одном диске, а комнаты Demo Day хранятся в памяти.
