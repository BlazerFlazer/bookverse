# Запуск в интернете

Сайт и сервер работают на Vercel, база данных — Postgres, подключённый к проекту `server-9ndz`.

```
Браузер ──► blazverse.vercel.app (проект web)
               └─ /api ──► server-9ndz.vercel.app (функция) ──► Postgres
```

Запросы `/api` идут через сайт, поэтому cookie остаются своими для него. На компьютере ничего не меняется: локальный запуск по-прежнему использует SQLite.

## Что работает и что нет

| Возможность | На Vercel |
|---|---|
| Каталог, чтение, словарь, прогресс, аккаунты | работают |
| Обновления без перезагрузки страницы | нет, сокеты выключены |
| Живой Demo Day с голосованием | нет |
| Telegram-бот | нет, боту нужен постоянный процесс |
| Письма восстановления пароля | нет, SMTP не настроен |

Функция Vercel запускается на время запроса и не хранит состояние между запросами, а голосованию и боту нужен постоянно работающий процесс. Для Demo Day запускайте проект на своём компьютере по [DEMO_DAY.md](DEMO_DAY.md). Аккаунты на сайте и на компьютере не связаны: это разные базы.

## Как устроена сборка

Сервер собирает проект `server-9ndz`, корневая папка `apps/server`:

1. Vercel находит точку входа `apps/server/index.mjs`.
2. `npm run vercel-build` запускает `deploy/vercel-build.mjs`. Скрипт меняет в схеме Prisma SQLite на Postgres только на сборочной машине и собирает `src/vercel.ts` в один файл.
3. При выпуске в production он же обновляет таблицы и загружает книги. Для этого используется `prisma db push` без сброса базы: если изменение грозит потерей данных, сборка остановится.

Адрес сайта для сервера записан в `apps/server/index.mjs`, адрес сервера для сайта в `apps/web/vercel.json`. Если адрес изменится, поправьте эти файлы.

## Как выпустить новую версию

Vercel выпускает в production всё, что попадает в ветку `main`. Проверить перед выпуском можно на предпросмотре: он создаётся для каждой ветки, таблицы и книги при этом не меняются.

## Если нужен живой Demo Day в интернете

Понадобится хостинг с постоянным процессом и диском. Для него готовы [Dockerfile](../Dockerfile) и `deploy/start.mjs`: сервер, бот и база SQLite работают в одном контейнере, а при старте применяются миграции и загружаются книги. Сам `Dockerfile` ещё не собирался.

На Railway это выглядит так:

1. New Project → Deploy from GitHub repo. Railway сам найдёт `Dockerfile`.
2. Подключите диск с путём `/data`, иначе база будет стираться при каждом обновлении.
3. Задайте переменные `PUBLIC_WEB_URL`, `TRUST_PROXY_HOPS=2`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME`, `BOT_INTERNAL_SECRET` и `DEMO_PRESENTER_KEY`. Секреты вводятся только там и никогда не попадают в репозиторий.
4. Остановите бота на своём компьютере: Telegram не даёт двум процессам получать сообщения одного бота.
5. В `apps/web/vercel.json` замените адрес сервера, добавьте правило для `/socket.io/:path*`, а в настройках проекта `web` задайте `VITE_REALTIME_URL` с адресом сервера.

Условия на 31 октября 2026 года: пробный период даёт разовые $5 на 30 дней без карты, дальше тариф Hobby от $5 в месяц с картой. Сервер с ботом занимает около 250 МБ памяти, что при цене $10 за ГБ в месяц даёт примерно $2,5 плюс процессор и диск.

Сервер должен работать в одном экземпляре: база лежит на одном диске, а комнаты Demo Day хранятся в памяти.

## Ограничения

- Лимит запросов считается по адресу посетителя, но телефоны в одной школьной сети выглядят для сервера как один адрес. На обычные запросы действует лимит 600 в минуту, на вход и регистрацию 20.
- `TRUST_PROXY_HOPS` верит заголовку `X-Forwarded-For`. На постоянном хостинге, обратившись к серверу напрямую, можно подделать свой адрес и обойти лимиты.
